# Plan: Add .m3u8 Playlist Link Support

## Context
The app currently plays video links (typically iframe embeds like YouTube) inside an `<iframe>` element. The user wants to add support for `.m3u8` (HLS) streaming URLs that play directly in the browser using a native `<video>` player, without breaking the existing iframe embed workflow.

## Approach
Add a `<video>` element alongside the existing `<iframe>`. When loading a video, detect if the URL is an `.m3u8` HLS stream — if so, use `hls.js` (via CDN) to play it in the `<video>` element; otherwise, continue using the `<iframe>` for embeds.

## Changes (all in `index.html`)

### 1. Add hls.js CDN script
- Add `<script src="https://cdn.jsdelivr.net/npm/hls.js@latest"></script>` in the `<head>` section.

### 2. Add `<video>` element in HTML
- Add a `<video>` element next to the existing `<iframe>` inside `.fullscreen-wrapper`, with the same fullscreen absolute positioning styles.
- Give it `id="videoPlayerNative"`, `controls`, `autoplay`, and `display: none` by default.

### 3. Add CSS for the video element
- `.fullscreen-wrapper video` — same absolute positioning/styling as the iframe (position absolute, full width/height, border none, display none).

### 4. Add URL detection helper
- Function `isM3u8Url(url)` that returns `true` if the URL contains `.m3u8` (case-insensitive). This handles URLs with query params too (e.g. `stream.m3u8?token=abc`).

### 5. Modify `updateUI(reloadVideo)` function
- When `reloadVideo` is true and there's a valid current item:
  - If `isM3u8Url(currentItem.url)`:
    - Hide iframe, show video element
    - Use `Hls.js` to load the stream into the `<video>` element (with fallback to native HLS for Safari)
  - Else:
    - Hide video element, show iframe
    - Set iframe `src` as before (existing behavior, untouched)
- When playlist is empty, hide both elements.

### 6. Add HLS cleanup
- Store the `Hls` instance in a variable (`let hlsInstance = null`).
- Before loading a new source, destroy the previous hls instance (`hlsInstance.destroy()`) to prevent memory leaks.

### 7. Update format hint text
- Update the editor panel's format hint to mention m3u8 support:
  `"Format: Episode_Number|URL (supports embed links and .m3u8 streams)"`

## Files Modified
- `index.html` — single file, all changes here

## Key Safety Considerations
- The iframe embed path remains completely untouched — same logic, same element.
- The video element and hls.js are only activated when a `.m3u8` URL is detected.
- hls.js is loaded from CDN (jsdelivr), no local files needed.
- Safari has native HLS support — the code checks `Hls.isSupported()` and falls back to native `<video>.canPlayType`.

## Verification
- Test with a regular embed URL (e.g. YouTube embed) — should work as before via iframe.
- Test with a `.m3u8` URL — should play in the native video player with controls.
- Test switching between m3u8 and embed URLs in the same playlist — both should work seamlessly.
